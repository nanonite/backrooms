# Issue 259: trees and foliage for open-world inputs

## Problem and constraints

The snow-garden v2 candidate builds six-sided, solid-material cylinder trunks, four small cylinder branches per tree, and, for two canopy variants, two thin textured boxes; its leafy variant uses flattened textured spheres and bare trees omit canopies. Trunk collision is a separate box. Tree positions and dimensions are authored, not measurements ([room.gd](../../godot_walk/source_library/sources/video-d92fc1fa764aa3a2/rooms/snow-garden-courtyard-v2/room.gd)). Its crop manifest records source imagery and crop provenance ([crop_manifest.json](../../godot_walk/source_library/sources/video-d92fc1fa764aa3a2/rooms/snow-garden-courtyard-v2/textures/crop_manifest.json)). The #255 report describes a photoreal, unbounded park in the panorama versus a bounded courtyard, and explicitly identifies solid-colour trunks and canopies that look flat from some angles; its author also identifies the tree layout as invented and the sky as static ([REPORT.md](../../godot_walk/evidence/2026-11-17-issue-255-room-candidate/REPORT.md)). Fixing foliage alone cannot establish a continuous open world.

The report describes the candidate as pending at report time; the later operator record accepts that exact identity as a bounded standalone room, without accepting catalog admission, connectivity, registration, or metric scale ([operator_review.json](../../godot_walk/source_library/sources/video-d92fc1fa764aa3a2/rooms/snow-garden-courtyard-v2/operator_review.json)). Another accepted standalone example has the same limited scope ([slot-canyon operator review](../../godot_walk/source_library/sources/video-22909eb734e4d8e2/rooms/slot-canyon-courtyard-v1/operator_review.json)). Acceptance of either is not evidence that a new foliage representation is accepted. The source-library workflow preserves prior manifest hashes and requires separate operator approval and catalog admission before linking an immutable candidate ([README.md](../../godot_walk/source_library/README.md)). The existing room completion freeze pins paths and hashes and has a v3 ancestor; it is a compatibility boundary, not an open-world foliage specification ([contract_freeze_v4.json](../../godot_walk/room_catalog/contract_freeze_v4.json)). Keep existing pinned assets untouched, and keep `registration_accepted` and `scale_calibrated` false in any successor. These proposals do not assert video connectivity or source-derived dimensions.

## Options

Costs below are relative estimates, not benchmarks. All proposals need source rights/provenance checked before reuse; no external tool or paper capability is relied on here.

1. **Textured trunk and layered source-crop cards.** Replace a trunk's solid surface with a provenance-recorded bark crop when an appropriate source region exists; arrange several differently oriented and vertically offset canopy cards around branch geometry. Keep collision independently authored. Cost: low to medium authoring and capture effort, with more surfaces and possible overdraw. Risk: repeated crops, visible edges and silhouette gaps remain, especially from above or close up; a usable bark crop may not exist. An agent can check file provenance, card orientations, bounds, collision and capture reproducibility; only the operator can judge whether the views are sufficiently natural and faithful to the source.

2. **Authored low-poly tree mesh with textured foliage clusters.** Make a tapered, branched trunk and several volumetric clusters, with source-backed textures where suitable and explicitly labelled authored surfaces elsewhere. Cost: medium to high manual modeling, UV work and asset review; potentially more geometry. Risk: invented geometry or unsuitable crops may look convincing while overstating source evidence, and silhouettes may still repeat. An agent can check asset references, geometry bounds, collision and provenance; the operator must judge visual fidelity and acceptable invention.

3. **Reconstruct a tree from multiple source views.** Investigate a separately authorized reconstruction workflow and bring a bounded, versioned result into a candidate if source views support it. Cost: high and uncertain capture, processing and cleanup; model or GPU work would require operator go-ahead. Risk: occlusion, motion and inconsistent views may produce incomplete geometry; external reconstruction tool capabilities and resource requirements are **unverified** here. An agent can audit input provenance and, once authorized results exist, inspect assets and run mechanical checks; the operator must decide whether reconstruction quality and inferred details are acceptable. No reconstruction was run for this research.

## Recommendation

Start with option 1 as a small, reversible visual experiment. It directly addresses both observed cues using the existing crop-based approach, keeps authored collision separate, and provides an inexpensive comparison before investing in modeled or reconstructed geometry. This is a hypothesis: layered cards may still look flat, and failure should lead to option 2 or further research rather than an automatic approval. Use a new candidate or isolated test fixture; never overwrite the accepted candidate or its pinned inputs.

## Ready-to-file first implementation slice

**Title:** Prototype source-backed trunk and layered canopy for one open-world tree

**Scope:** In a new, versioned isolated fixture, build one tree using a source-backed bark crop if a suitable crop can be identified, plus several spatially separated canopy cards with varied orientations using traceable existing or newly extracted source crops. Record source paths, crop coordinates and hashes, and label authored placement and geometry. If no appropriate bark crop exists, document that finding and retain an explicitly authored trunk appearance rather than claiming a source-backed texture. Preserve separate trunk collision and a traversable inspection path. Do not change the accepted snow-garden room, frozen contracts, shared pinned files, registration or scale flags. No model, GPU, download, catalog admission or implied connectivity is part of this slice.

**Acceptance:** The fixture includes the tree, crop provenance and authored-versus-source notes; its trunk collision is independently defined; canopy cards have multiple orientations and depth offsets. Provide matched front, side, oblique, close and elevated views with camera positions recorded, alongside a baseline view of the current representation. Record any remaining silhouette, crop-edge, repetition and collision limitations. Do not describe a visual pass or source fidelity as operator approval. Keep `registration_accepted=false` and `scale_calibrated=false` wherever those flags are recorded.

**Verification:** Agent checks the fixture loads, source/crop hashes and references resolve, card transforms differ, and the player cannot pass through the trunk while the inspection route remains usable. Run the relevant existing automated checks and record exact commands and results. Capture the matched views only in an authorized environment with the required rendering access; report unavailable checks rather than substituting synthetic results. The operator compares the views with the source and decides whether visual quality warrants a successor issue; any acceptance or catalog admission follows its separate workflow.

## Unknowns not tested

- Whether any available source frame contains enough unobstructed bark for a useful crop, or whether crop reuse rights are adequate.
- Whether layered cards improve silhouette from all viewpoints, avoid visible rectangular edges, or retain the desired style at walking distance.
- Actual rendering, overdraw, memory and frame-time costs in a representative open-world scene; no performance budget was measured.
- Whether source video has sufficient multi-view coverage for reconstruction, or which reconstruction tools and resources would work.
- Placement, density, occlusion, continuous terrain, streaming and collision behavior across an open world; no source registration, metric scale or connectivity was established.
- No new runtime, visual capture, model, GPU or download was performed for this research. Existing report results are historical evidence, not fresh verification ([REPORT.md](../../godot_walk/evidence/2026-11-17-issue-255-room-candidate/REPORT.md)).
